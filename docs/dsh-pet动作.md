# cuteQ 0.3：dsh-pet 连续视频动作

动画来源：[PC2005-cloud/dsh-pet](https://github.com/PC2005-cloud/dsh-pet)，固定提交 `48007b64ac0bebb2e97ac88344aed62de8399dd4`。保留了上游 README、MIT 代码许可及非商业素材条款，见 [素材索引](../assets/dsh-pet/SOURCE.md)。当前为本机个人使用版本。

## 播放与活动节奏

使用原生 VP9 透明视频，源尺寸 640×360、24 帧/秒。画布刷新与视频解码分开，普通动作保持 1 倍速；落地、拖拽的整体变形和窗口位移可按屏幕刷新率更新。没有使用生成式视频模型，也没有把 24 帧素材标成 60 帧。

运行时固定两个视频元素。一个显示当前段，另一个提前定位到循环起点；新段准备好才切换，旧段继续保留画面。不再预解码几千张 PNG。待机、睡眠停留和减少动画会暂停视频。命中区域通过 160×90 的透明度缓存计算，不保存整套逐帧掩码。

吃白饭完整时长 25.71 秒。视频以原速播放，在源视频 2.5–6.5 秒之间额外循环四次，再继续放下饭碗和收势。循环位置经过画面相似度比较；没有将 10 秒视频整体拉慢。普通手动动作约 9.71 秒。睡眠播放到 7.5 秒后停留，醒来从同一时间继续。

转身先播放 1.75 秒再移动。步态跟随实际移动距离，缓起步和刹车同步调整播放速度；向右散步使用侧向视频的镜像。停下使用收势段。运行中不会播放那段带摔倒的奔跑素材。

仍沿用原有安静调度：静态待机；轻活动间隔 45–90 秒；首个饭点等待 4–7 分钟，后续间隔 5–9 分钟；散步约每 3–5 分钟尝试。专注、安静、全屏、聊天忙碌时不会自动插入饭点或跳舞。用户主动操作优先。

## 动作对应

23 段实际使用素材覆盖 18 个面板入口和事件状态。部分表情共用同一个视频，过渡段也来自同一视频，不能把内部状态数量当作独立动作数量。

| 入口或事件 | 使用素材与处理 |
| --- | --- |
| 摸摸 | 点击回应-挠痒咯咯笑 |
| 慢慢吃白饭、自动饭点 | 吃白饭，原速中段循环至 25.71 秒 |
| 打招呼 | 点击回应-元气挥手 |
| 跳舞 | 轻快摇摆舞 |
| 庆祝 | 点击回应-开心跃动；得意表情另用工作状态-雀跃庆祝 |
| 原地踏步 | 原地漂浮踏步 |
| 偷吃、饥饿、满足 | 偷吃零食被抓住；满足从后段开始 |
| 写写画画 | 轻快记录 |
| 震惊、惊讶 | 被吓一跳、点击回应-害羞惊讶 |
| 赌气、抗议 | 点击回应-傲娇生气 |
| 行个女仆礼 | 女仆屈膝礼仪 |
| 哼歌、魔方、尾巴拍地、舒展 | 悠闲哼歌、原地专心玩魔方、用鲸鱼尾巴拍打地面、超大伸懒腰 |
| 思考 | 工作状态-思考冒泡 |
| 待机与轻活动 | 待机呼吸休闲；待机冻结在末尾，轻活动只取前段 |
| 小憩、醒来 | 原地小憩沉眠，分入睡、停留与苏醒 |
| 拖动、下落 | 被鼠标拖拽悬空反馈，拖动停在悬空姿势，下落沿用同姿势 |
| 落地 | 原地重力下蹲压缩的后段 |
| 左右散步、转身和停步 | 螃蟹走路，分段并按方向镜像 |

## 验收与限制

运行 `npm test` 验证行为、时间轴、共享记忆和透明窗口支点；`npm run test:animation` 验证所有状态的实际解码、透明度、逐段切换、完整饭点、待机停止、减少动画和两个解码器上限。`node scripts/walk-qa.cjs` 检查真实左右窗口位移、距离驱动的步态和浏览器播放错误。`node scripts/video-hit-qa.cjs` 检查身体与透明区域的鼠标命中，覆盖左右镜像与拖动变形。`npm run test:integration` 使用隔离配置、模拟模型与中文音频文件验证语音、聊天和持久记忆，不录制真实麦克风或调用付费模型。

本机结果和可查看的连拍图保存在 `artifacts/animation-qa-v03/`；最终数据见 `artifacts/0.3-验收结果.md`。0.2 两个可执行文件保留，便于比较。

素材本身仍有少量抠像边缘、部分道具初始姿势差异和 24 帧的运动节奏，少数向画布外扩散的音符或爱心会被窗口裁切；视频连续不等于每个动作之间都有专门绘制的过渡。默认大小接近源角色像素密度，更高屏幕缩放会放大原图。仍需用户实际体验来判断是否符合其对“自然”的偏好。
